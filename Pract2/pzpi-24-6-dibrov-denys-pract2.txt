2 ЗАВДАННЯ


Метою практичного завдання є дослідження методів рефакторингу коду для мови програмування C#, а також практична демонстрація рефакторингу коду.
Основні завдання:
1. Ознайомитися з методами рефакторингу програмного коду, описаними у книзі Мартіна Фаулера «Refactoring: Improving the Design of Existing Code».
2. Обрати три методи рефакторингу з переліку, наведеного в методичних вказівках.
3. Проаналізувати власний програмний код та визначити ділянки, до яких доцільно застосувати обрані методи рефакторингу.
4. Для кожного обраного методу навести початковий фрагмент коду, визначити проблему, яку необхідно усунути, та продемонструвати результат після рефакторингу.
5. Пояснити сутність виконаних змін і переваги їх застосування з погляду покращення якості, читабельності та структури програмного коду.
6. Підготувати презентацію на 12 слайдів українською мовою;
7. Зробити відеозапис доповіді тривалістю 7–9 хвилин та завантажити його на YouTube;
8. Оформити звіт, включивши опис виконаної роботи, висновки, список джерел та додатки А (відео), Б (слайди), В (програмний код).










3 ОПИС ВИКОНАНОЇ РОБОТИ
3.1 Загальна характеристика програмного проєкту 


Для виконання практичної роботи було використано власний програмний проєкт AutoListGoogleMeet, розроблений мовою програмування C# із використанням Windows Forms.
Програма призначена для обробки CSV-файлів із даними про відвідуваність онлайн-зустрічей Google Meet. Вона дозволяє отримувати список учасників зустрічі, визначати дату та код зустрічі, порівнювати присутніх із еталонним  списком студентів, а також зберігати інформацію про навчальні предмети.
Під час аналізу вихідного коду було визначено декілька ділянок, які можна покращити за допомогою методів рефакторингу. Для цього було обрано три методи з книги Мартіна Фаулера «Refactoring: Improving the Design of Existing Code»:
* Replace Magic Number with Symbolic Constant;
* Replace Data Value with Object;
* Separate Domain from Presentation.
Кожен метод було застосовано до відповідної частини програмного коду з метою покращення його читабельності, структури та розподілу відповідальності між класами.


3.2 Застосування методу Replace Magic Number with Symbolic Constant


Під час аналізу методу LoadStudentsFromFile() та допоміжного методу ExtractDataFromCSV() було виявлено використання числового значення 10 без пояснення його призначення.
Це значення обмежувало кількість рядків CSV-файлу, які перевірялися під час пошуку метаданих зустрічі. Зокрема, воно застосовувалося під час пошуку коду зустрічі та визначення дати проведення.
Використання числового значення безпосередньо в кількох місцях ускладнювало розуміння його призначення. Крім того, зміна кількості рядків для перевірки потребувала б редагування кількох ділянок коду.
Для усунення цієї проблеми було застосовано метод Replace Magic Number with Symbolic Constant [1, с. 166]. Числове значення було замінено іменованою константою:


1. private const int METADATA_LINES_COUNT = 10;


Після цього всі відповідні виклики, які використовували це число, було замінено на константу METADATA_LINES_COUNT.
У результаті призначення числового значення стало зрозумілішим, а його зміна тепер потребує редагування лише одного оголошення. При цьому логіка та поведінка програми залишилися незмінними.


3.3 Застосування методу Replace Data Value with Object


У початковій реалізації програми код зустрічі Google Meet зберігався у звичайній змінній типу string. Використання типу string не відображало семантичного призначення значення, а правила перевірки формату коду не були інкапсульовані в окремому типі. 
Для покращення структури коду було застосовано метод рефакторингу Replace Data Value with Object [1, с. 141]. Його суть полягає в заміні простого значення окремим об’єктом, що представляє конкретне поняття предметної області.
Для цього створено клас MeetCode із властивістю Value, яка зберігає текстове представлення коду зустрічі. Конструктор класу зроблено приватним, щоб запобігти створенню об’єктів із некоректними значеннями поза межами класу.
Також реалізовано статичний метод TryParse(), який перевіряє відповідність вхідного рядка формату коду зустрічі. Об’єкт MeetCode створюється лише після успішної перевірки.
Після цього тип змінної currentMeetCode у класі Finder змінено зі string на MeetCode. Для отримання текстового значення коду використовується властивість Value.
Водночас словник Subjects залишився без змін і продовжив використовувати рядкові ключі. Це дозволило зберегти наявну структуру JSON-файлу та уникнути зайвих змін у механізмі збереження налаштувань.
У результаті код зустрічі отримав окреме представлення у програмі, а перевірка його формату була інкапсульована в спеціалізованому класі.


3.4 Застосування методу Separate Domain from Presentation 


Під час аналізу початкової реалізації методу LoadStudentsFromFile() було виявлено, що він виконував декілька різних завдань одночасно.
Метод відповідав за читання CSV-файлу, пошук коду зустрічі та дати, отримання списку учасників, а також безпосереднє оновлення елементів графічного інтерфейсу Windows Forms.
Таке поєднання логіки обробки даних і відображення результатів ускладнювало підтримку та подальше розширення програми.
Для усунення цієї проблеми було застосовано метод Separate Domain from Presentation [1, с. 302], який передбачає відокремлення логіки роботи з даними від логіки представлення.
Спочатку було створено клас GoogleMeetCsvData, призначений для зберігання результатів обробки CSV-файлу. Він містить властивості MeetCode, MeetingDate та Students, у яких зберігаються код зустрічі, дата проведення та список учасників відповідно.
Після цього було створено клас GoogleMeetCsvParser, до якого перенесено логіку читання та аналізу CSV-файлів. Його основний метод Parse() виконує обробку файлу, знаходить необхідні дані та повертає результат у вигляді об'єкта GoogleMeetCsvData.
У класі Finder було змінено реалізацію методу LoadStudentsFromFile(). Тепер він використовує GoogleMeetCsvParser для отримання оброблених даних, після чого відповідає за їх відображення в елементах графічного інтерфейсу, взаємодію з користувачем та збереження інформації про предмети.
Таким чином, обробка CSV-файлів була відокремлена від графічного інтерфейсу. Це дозволило чіткіше розподілити відповідальність між класами та спростити підтримку відповідної частини програми.
















4 ВИСНОВКИ


У процесі виконання практичного завдання було розглянуто методи рефакторингу програмного коду та досліджено можливості їх застосування для покращення структури програмного забезпечення. Практичну частину роботи було виконано на основі власного проєкту AutoListGoogleMeet, розробленого мовою C# із використанням Windows Forms.
У процесі роботи було обрано та застосовано три методи рефакторингу: «Replace Magic Number with Symbolic Constant», «Replace Data Value with Object» та «Separate Domain from Presentation».
Метод «Replace Magic Number with Symbolic Constant» [1, с. 166] дозволив замінити числове значення іменованою константою, що зробило його призначення зрозумілішим. Застосування «Replace Data Value with Object» [1, с. 141]  передбачало створення окремого класу MeetCode для представлення коду зустрічі та перевірки його формату. Завдяки методу «Separate Domain from Presentation» [1, с. 302] обробку CSV-файлів було відокремлено від логіки графічного інтерфейсу шляхом створення класів GoogleMeetCsvParser та GoogleMeetCsvData.
Унаслідок внесених змін покращено читабельність і організацію програмного коду, а також розподіл відповідальності між класами.
Виконана робота продемонструвала практичне застосування методів рефакторингу в реальному програмному проєкті та підтвердила можливість покращення читабельності й структури коду без зміни основної функціональності програми.
